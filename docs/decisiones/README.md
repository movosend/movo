# Registro de decisiones de diseño — resumen

Decisiones de alcance acotado (una regla de negocio, el detalle de un solo módulo, un contrato de endpoint o un parámetro) que no fijan el stack, un proveedor, la estructura entre servicios ni el modelo de seguridad, y por eso no son ADR (criterio en [`docs/adr/README.md`](../adr/README.md)). En Drive viven en `[Movo] 011-Registro de Decisiones de Diseño`.

Prefijo `DD-` y **número original**: es el que tenían como ADR antes del recorte a 23, así que los tickets de Linear y los comentarios viejos que digan "ADR-0xx" con uno de estos números se leen como `DD-0xx`. Una decisión de diseño aceptada tampoco se modifica: si cambia, se crea una nueva que referencia y reemplaza a la anterior. El desarrollo completo está en el borrador que cita cada fila.
